# Архитектура проекта

Проект - статический сайт без backend-сервера. Основная логика работает в браузере.

## Основные файлы

- `index.html` - базовая разметка приложения.
- `styles.css` - визуальный стиль, темы, панели, граф.
- `app.js` - базовая логика приложения.
- `app-patch.js` - улучшенная логика построения и раскладки графа.
- `selection-patch.js` - навигация, выбор блоков, правая панель, ручное перемещение.
- `history-patch.js` - история построенных схем.
- `export-patch.js` - экспорт SVG, PNG и draw.io.
- `faq-patch.js` - FAQ вместо кнопки примера.
- `field-edge-patch.js` - подсветка стрелок, добавление поля в SDL, сохранение ручных позиций.
- `reference-links-patch.js` - кликабельные ссылки на типы в правой панели.
- `edge-clear-patch.js` - сброс залипшего выделения стрелок.

## Почему есть patch-файлы

Проект развивался итеративно. Чтобы не ломать уже рабочую логику, новые функции добавлялись отдельными слоями. Это позволило быстро исправлять:

- поведение стрелок;
- экспорт;
- историю;
- правую панель;
- ручное перемещение блоков;
- кликабельные типы;
- сброс залипшего выделения.

## Как устроен граф

1. SDL или introspection JSON парсится в набор типов.
2. Каждый тип становится node.
3. Поля, которые ссылаются на другие пользовательские типы, становятся edge.
4. Edge привязывается к конкретному полю источника.
5. SVG перерисовывается при изменении схемы, масштаба, фильтров или ручных позиций.

## Состояние в браузере

Часть состояния хранится в JS-памяти страницы:

- выбранный блок;
- выбранная стрелка;
- ручные позиции блоков;
- текущий масштаб и сдвиг холста.

История построений хранится локально в браузере.

## Ограничения

- Нет backend API.
- История не синхронизируется между устройствами.
- Introspection-запрос из браузера зависит от CORS сервера.
- Большие схемы могут требовать широкого холста и ручной донастройки.
